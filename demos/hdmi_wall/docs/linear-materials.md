# 线性解码接入与指定素材验收（2026-09-28）

本页记录 09-28 的吞吐优先配置：**官方 1080p24、每卡 32 路、线性输出、8 块额外解码缓冲、输出复用、64 KiB 合并预算、每路预览上限 3 FPS、墙面合成不限频**。不抽帧，不关闭检测结果回传，不修改素材帧率。此配置在本板 PCIe2 ×1 / PCIe3 ×1 双卡并行测试中，正式窗口的 TPU 采样均为 100%。其他素材放在 stress 用法中按路数验证。

## 如何选择配置

- 观看画面：按[五档布局与流畅度](layouts.md)选择路数，使用 `--preview-fps -1 --display-fps 30`；本轮 4 / 8 路接近源视频 24 FPS，32 路为 7.5–8.7 FPS。
- 复现本页吞吐数据：显式指定每卡 32 路、预览 3 FPS、播放器 10 FPS。下表各项成绩与该配置绑定，不能用来描述不限频预览的速度。

入口仍支持选择 1–4 张卡，32 路不是所有场景的固定要求。

## 复现吞吐优先配置

在板端仓库根目录执行，沿用已配置的 DISPLAY / XAUTHORITY。入口支持 1–4 张卡：`--devices auto` 自动选择当前设备，也可显式指定单卡或多卡；设备编号与链路以现场查询为准。

```bash
# 复现历史吞吐配置：显式指定参数，无需附加 profile 或 LD_PRELOAD。
sudo bash demos/hdmi_wall/showcase.sh --devices auto --duration 300 --streams 32 --preview-fps 3 --display-fps 10

# 上一轮结束后，测试指定的 highway 1080p25，已测配置为每卡 24 路。
sudo bash demos/hdmi_wall/showcase.sh --mode stress --devices 0,2 \
  --input data/inputs/highway_1080p25.mp4 --streams 24 --duration 300

# 提前结束当前多卡任务。
sudo bash demos/hdmi_wall/showcase.sh --stop
```

省略 duration 仍为 4 小时。**本次是短测，尚未完成四小时认证，也不保证未来每次 TPU 采样都为 100%。** `--devices auto` 会选入现场识别到的所有设备（1–4 张）。下表是指定双卡的历史测试；后续[三卡五分钟结果](three-card.md)单独记录，四卡尚未上板验证。手动覆盖输入、路数、profile 或预览参数后，需要重新验证，不能沿用标准展示结论。

## 怎样理解这些成绩

总 INF 是每张卡全部通道合计的检测帧率。280.30 / 281.43 FPS 对应平均每路约 8.76 / 8.79 FPS，低于源视频每路 24 FPS；“不抽帧”指每帧均进入解码获取流程，latest 调度仍会覆盖等待中的帧。[性能说明](../../../docs/performance-overview.md) · [已核对的数据摘要](data/linear-showcase-20260928.json)。

## 正式入口实测

所有记录均使用真实 `showcase.py → multi_run.py → hdmi_wall.pcie + viewer.py`，两卡同时运行，YOLOv8s INT8、gate on、latest、送检年龄门槛 250ms、summary、首帧预取。每轮正式 60 秒，另有 3 秒预热和初始化；检测结果回传始终开启，`model_only_measured=0`。

最终 showcase 两卡各有 12 个有效 TPU 样本，最小、最大、平均全部是 100%，不是只挑峰值；最长无推理结果间隔分别为 0.1784 / 0.1453 秒。前一轮同参数测试也各有 12 个 100% 样本。

highway 24 路 stress 的最长结果间隔为 0.4648 / 0.4371 秒，过期帧为 27 / 32；预览 10 FPS 对照为 0.3426 / 0.7527 秒、37 / 154 帧。这里“通过”表示本轮所有通道持续有推理结果、最长间隔低于 2 秒、计数完整且无工作线程错误，**不表示每个输入帧都得到推理，也不表示零丢帧**。latest 原本就允许覆盖等待帧。

因此，highway 25p 的 24 路可以作为指定素材测试配置，但没有纳入“双卡所有正式 TPU 样本均为 100%”的标准 showcase。没有把它偷偷转成 24p 或全 I 帧。

## 共用实现

- `demos/common/device_capture.hpp` 直接配置 SOPHON FFmpeg 的 `output_format=0`、`extra_frame_buffer_num=8`、`zero_copy=1` 和实际设备编号。当前原生路径选择 H.264 / H.265 硬件解码器；本次多路验收素材均为 H.264。其他格式可以显式选择 `--decoder opencv`，但不适用本次性能结论。
- 解码器上下文与借用图像共享生命周期。EOF / 重开捕获入口时，仍被推理或异步预览使用的设备图像会保留旧解码器；图像先释放，上下文后释放。EOF 会排空延迟帧，避免漏掉 B 帧尾部。
- `run.py` / `multi_run.py` 共用解码、缓冲、抽帧和墙面参数；showcase / stress 默认启用线性路径。普通 run / multi_run / benchmark 保留 OpenCV 默认路径用于兼容对照。
- 指定素材通过 `--input` 传入准备脚本；按输入路径分开缓存，继续校验输入和输出 SHA-256。只循环复制视频压缩包，不重编码或改帧率。
- `--retrieve-every 2` 可显式开启，但默认仍为 1。它不会跳过编码依赖帧的解码；此前在线性输出后没有明显额外吞吐收益，不能用它承诺解决 32 路 highway STALE。

完整参数见[命令参数](parameters.md)。8 指额外解码缓冲，不是推理队列长度；16 缓冲的旧实验被设备拒绝，本实现不开放该值。
