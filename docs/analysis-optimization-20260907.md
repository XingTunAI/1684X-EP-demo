# 单卡多路分析性能与图像路径优化（2026-09-07）

## 统计方式

本轮按性能摸底记录，不以 25 FPS 判通过或失败。25 FPS 是视频输入帧率；每帧都分析，不抽帧。正常完成状态是 `measured`，仅说明测量完成并且输出完整，不是生产容量验收结论。进程退出、长时间停帧和输出不完整仍记录为运行异常。

所有结果位置使用工程内相对路径。旧报告的验收状态按当时配置保留，不能回改为通过。

## 固定配置

- RK3588 主机、物理卡 1 / device 1、PCIe 3.0 ×1。
- YOLOv8s INT8 batch 1，每路独立进程和模型实例，不画框、不编码。
- 输入视频：`datasets/stress/bbb_1080p25_h264_8mbps_20min.mp4`，1080p25 H.264。
- 32 路测试统一预热 180 秒、正式采集 120 秒、统计窗口 60 秒，停帧超时 180 秒。
- `model_tool --info` 确认模型输入为 `[1,3,640,640]` float32，输出为 `[1,8400,84]` float32。文件名的 INT8 指模型内部量化，并不说明输入输出张量都是 INT8。

## 图像路径对照

原路径默认输出 BGR，再通过 `toBMI(update=true)` 交付图像。实验路径使用 SDK 的 YUV 输出及设备图像接口，避免无 CPU 像素修改情况下的重复同步。相关接口说明见 [SOPHON Multimedia 0.14.0](https://doc.sophgo.com/sdk-docs/v23.09.01-lts-sp5/docs_latest_release/docs/sophon-mw/guide_en/html/guide/Multimedia_Guide_en.html)。

YUV 单路功能短测 `20260907_144232_82383`：预热 5 秒、采集 15.18 秒，窗口 24.91 / 24.89 / 25.13 FPS，正常输出 501 帧检测记录。取帧均值 1.68 ms，图像交付均值 0.007 ms。这个短测不能代替长测，也不代表最大吞吐。

与原 BGR 手动单路测试对齐前 501 帧：318 帧检测列表完全相同，406 帧类别集合（含数量）相同，总框数分别为 323 与 318。YUV 直接预处理改变了颜色转换/缩放路径，结果存在差异，不能宣称检测结果等价。后续还需使用标注业务数据验证准确率，并对照保留 BGR 中间图像的设备内转换路径。

32 路 YUV 对照已完成，编号 `20260907_144341_82720`，正式采集 120.48 秒。总平均 114.59 FPS，各路平均 3.43～3.80 FPS，最低逐路窗口 3.27 FPS，32 路检测记录完整、正常收尾，stderr 全空。总吞吐约为原 BGR 路径的 3.51 倍，但检测结果等价性尚未确认，因此保留为可选实验路径。

YUV 32 路阶段均值（各路均值再等权平均）：取帧 6.16 ms，图像交付 0.008 ms，预处理 5.98 ms，推理调用及同步 4.58 ms，后处理 261.93 ms。减少图像往返后仍有较大后处理开销，需要进一步细分输出张量传输、CPU 遍历/NMS与并发等待。

结果目录：`results/board-analysis/20260907_144341_82720/`。

## 保留 BGR 中间图像的设备内转换

`--image-path device-bgr`：解码输出 YUV，在卡上转成完整 BGR 图像，再交给原有 RGB 预处理。CPU 不读写像素时使用 `update=false` 避免重复主机/设备同步，同时保留原路径的颜色转换和缩放次序。Mat 与借用的 bm_image 生命周期覆盖完整推理调用；转换失败或尺寸不符直接记录错误，不静默回退。

单路功能短测 `20260907_144940_84581`：预热 5 秒、采集约 20 秒，四个窗口 25.14 / 25.11 / 24.70 / 24.98 FPS。取帧均值 1.68 ms，设备转换和图像交付 1.51 ms，预处理 2.20 ms，推理调用及同步 2.93 ms，后处理 26.76 ms。未抽帧、未改模型、未降低输入或推理尺寸。

对齐原手动单路基线前 627 帧，627 帧检测 JSON 中的框、类别和置信度全部一致，两边各 374 个检测框。这是本素材前缀的回归核对，不能代替业务标注集的算法精度评测。

32 路 device-bgr 对照已完成，编号 `20260907_145114_84975`，正式采集 120.37 秒。总平均 **114.10 FPS**，平均每路 **3.57 FPS**，各路平均 3.31～3.75 FPS，最低逐路窗口 3.06 FPS。总吞吐为原 BGR 路径的 **3.49 倍**。32 路检测记录完整、收尾退出码均为 0，stderr 全空。

32 路累计 34,006 条检测记录与原手动基线按源帧编号逐条核对，34,006 条检测列表完全一致，没有超出基线范围的帧。各路重复使用同一素材，这不等于验证了 34,006 个不同场景。

阶段均值（各路均值等权平均）：取帧 7.33 ms，图像转换和交付 4.51 ms，预处理 7.66 ms，推理调用及同步 4.76 ms，后处理 255.56 ms。最大计划落后约 257.85 秒，表明此配置仍无法实时逐帧消费 32 路 25 FPS 输入。本轮按用户要求仅记录性能，不以 25 FPS 判失败。

analysis 入口默认采用 `device-bgr`；`--image-path bgr` 保留原路径对照，`--image-path yuv` 保留实验选项。encode 模式保持原 BGR 路径。结果目录：`results/board-analysis/20260907_145114_84975/`。


## TPU 能否跑满：独立模型计算实测

32 路视频测试结束后，在同一 device 1 上串行执行 batch 1、batch 4 的 BMRuntime 测试，每个模型内部重复计算 5,000 次。没有同时运行视频任务。结果目录：`results/board-tpu/20260907_150044/`。

| 模型 | 计算总时长 | 折算计算吞吐 | TPU 采样峰值 |
|---|---:|---:|---:|
| YOLOv8s INT8 batch 1 | 14.104249 秒 | 354.50 图/秒 | 100% |
| YOLOv8s INT8 batch 4 | 54.038635 秒 | 370.11 图/秒 | 100% |

折算方式为 `5000 × batch / calculate time`。每秒采样包含启动/收尾，batch 1 共 15 次采样，范围 0～100%；batch 4 共 54 次采样，范围 78～100%。两个模型均正常退出。本测试使用工具默认输入，只反复计算模型，不包含每帧的视频解码、传输、预处理和检测后处理，也不评估准确率，不能拿计算吞吐替代视频分析 FPS。

本次模型计算可以把 TPU 利用率推至 100%；视频流水线低利用率不能证明 TPU 算力已经耗尽。batch 4 在本次独立计算中仅比 batch 1 增加约 4.4% 图像吞吐，不能预期换成 batch 4 就有四倍性能。当前视频 worker 仍只支持 batch 1。

初次诊断 `20260907_145906` 显式设置了 `--thread_num 1`，工具进入多线程测试分支，未输出 calculate time 且很快退出。这次不是有效计算压测，原始记录保留并标记计时缺失，不纳入性能结论。最终脚本已去除此参数，计时缺失时报告不会生成吞吐数字。

独立计算一键复测（确认同卡视频任务已结束）：

```bash
python3 scripts/run_single_card_tpu_bench.py --device 1 --calculate-times 5000
```

设备输出 `results/tpu/日期时间/report.md`、`summary.json`、每个 batch 的日志和资源采样。下一步优化优先细分输出张量取回、候选框遍历/NMS 和调度开销，再评估共享推理及跨流批处理；以 32 路总吞吐、逐路帧率及输出正确性衡量收益，不单独追求利用率数字。
