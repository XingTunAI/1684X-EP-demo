# 抽帧后预览限频对照

后续已完成[四配置正反复测与回传耗时拆分](grab-preview-factors.md)，开关贡献与耗时解释以该报告为补充。

2026-09-28，RK3588 + BM1684X，device 0 / PCIe2 ×1。本报告只比较预览策略，所有配置均使用已经实现的“VPP展开前每2帧取1帧”，不改变其他解码设置。

## 测试方法

同一 `build-grab-select/hdmi_wall.pcie`，32路1080p24长素材、YOLOv8s INT8、latest、250ms年龄门槛、reuse、gate合并预算64KiB、同步预览、30秒预热＋60秒正式统计，按3FPS、10FPS、不限频顺序运行。各路独立读取同一素材，不是32个独立摄像头。原始目录为板端 `/userdata/1684X-EP-demo/data/results/grab-preview-20260928/`。

| 档位 | 单路预览生成限制 | 整墙主动限频 | ffplay输入帧率参数 |
|---|---:|---:|---:|
| 低回传 | 3 FPS | 10 FPS | 60 FPS |
| 提高预览 | 10 FPS | 10 FPS | 60 FPS |
| 取消应用限频 | -1：不限 | 0：不限 | 60 FPS |

播放器统一使用60FPS参数，以免原来的10FPS消费者设置影响比较；这不代表屏幕实测60FPS或全链路物理无限制。rawvideo没有逐帧时间戳，播放器按指定速率建立时间轴，因此需区分生成、管道提交、播放器呈现和显示器扫描输出。本次没有测量物理屏幕帧率或玻璃到玻璃延迟。

单路有效预览FPS按正式窗口内 `previews_submitted_measured / measured_seconds` 计算，32路求平均。TPU取正式区间遥测均值；推理与解码来自正式summary。整墙速率来自正式区间内status累计计数差，采用实际采样跨度，可能含重复内容，不能当作每路新画面FPS。源年龄是status采样值，不是摄像头端到端延迟。最长无分析结果间隔不是最长无预览间隔。

### 怎么理解效果

取消应用限频后，本轮有效预览为低回传档的3.57倍，平均约每117ms生成一张新图（原先约416ms）。运动跳跃间隔更短，但仍不是24/30FPS流畅视频。总推理比低回传档高约1.12%，预览回传量增加约21.85MB/s。

10FPS档吞吐低于另外两档，而不限频档更高，这说明本轮性能并不随回传字节数简单单调变化。不限频档同时改变单路生成和整墙调度两个条件，本轮没有分离其贡献，也没有反向重复，不能据此断言“不限频永远更快”。应先以此配置实际体验，再做长时及复测确认。

整墙46.78FPS会重复使用各通道最新缩略图，不能称为每路46.78FPS。屏幕物理呈现帧率没有测量；本报告能够确认的是预览生成与墙面提交。既有Rockchip GL加载报错仍存在，播放器未失败退出，不宣称显示链路完全无异常。

原始证据：各档 `command.json`、`state.json`、`worker/summary.json`、`telemetry.jsonl`、`stderr.log`，以及根目录 `comparison.json`、`wall-samples.jsonl`、`analysis.json`。本地也保存 `data/results/grab-preview-20260928/analysis.json`。初始metadata继承的steps字段已按各档实际命令更正，修正说明保存在metadata中；逐档命令是配置依据。

## 复现

先通过相应入口停止同卡实验。目录必须是新目录；脚本会为每档启动HDMI播放器，结束时清理本次子进程。

```bash
cd /userdata/1684X-EP-demo
sudo python3 tools/diagnostics/run_grab_preview_comparison.py \
  --device 0 --streams 32 --duration 60 \
  --modes 3,10,unlimited --player-fps 60 \
  --output "/userdata/1684X-EP-demo/data/results/preview-compare-$(date +%Y%m%d-%H%M%S)"
```

只体验取消应用限频，可用 `--modes unlimited --duration 300`。这仍使用独立实验构建，默认启动器和默认二进制未更换。提前停止按Ctrl+C。

## 边界

这是单次顺序短测，不是长稳或检测精度验收。取消单路预览限频会让更多检测帧执行缩图和回传，可能与推理争用VPP、DMA和主机资源。每2帧取1帧从24FPS源最多提供12FPS/路，实际预览还受推理吞吐约束，不会自动变成24FPS视频。
