## 公式和计时边界

```text
API平均调用时间 = 该API耗时总和 / 实际调用次数
API调用频率 = 正式窗口归属的调用次数 / 正式窗口秒数
有效数据率 = 对应字节总数 / 正式窗口秒数

候选单次读取均值 = row_read_ms.sum / row_read_calls
候选每检测帧总读取时间 = row_read_ms.sum / 完成检测帧数
```

`row_read_ms.count` 记录的是检测帧数，不能用它当候选单次读取的次数。调用耗时可进一步换算为每秒累计线程时间，但32路线程重叠，累计值可以超过1秒/秒，不能将其解释成总线、VPP或TPU利用率。

这些日志按当前检测及可选同步预览全部完成后的时间点归属正式窗口，少量调用可能跨越窗口边界。不是对所有调用采取“开始和结束均落窗”的统计。预览项的分母是实际小图次数，与检测项不同；本表也不能直接与异步预览的独立完成窗口混用。

`decode_ms` 只覆盖被选中推理的帧对应的读帧调用；本轮未开启全量decode_observation，不能据此推算所有768源帧/秒的VPU指令成本。`output_transfer_ms/output_copy_ms` 包含gate执行等开销，也不能当作纯PCIe回读时间。

## 尚缺的驱动层分账与采集办法

以下是第一轮账目复算时的采集方案。后续已完成分组追踪和独立寄存器读取，见[控制访问与驱动等待实测](pcie-dispatch-wait.md)：测到无追踪微秒级读取差异，但 32 路样本存在连续性失败和负载波动，尚不能给出稳定根因占比。不能将“已采到函数图”理解为“以下分账均已定量完成”。

板端支持 `function_graph`，分组追踪无需先修改驱动：

| 分组 | 建议根函数 | 要区分的时间 |
|---|---|---|
| VPP | bm1686_trigger_vpp | 等VPP名额、准备/上传描述符、上传内部CDMA锁等待、启动控制、完成等待 |
| DMA | bmdev_memcpy_s2d/d2s及internal路径 | 等暂存缓冲、等CDMA锁、持锁传输控制和完成等待 |
| TPU | bmdrv_send_api、bmdrv_thread_sync_api | 提交路径锁等待合计、FIFO空间等待、写消息、同步完成等待 |
| VPU | 需结合解码SDK标记、VDI等待及传输入口 | 码流提交、解码控制、等待输出；当前不能凭选中帧decode_ms替代全量测量 |

受控采集应保持同设备2、同插槽、同binary、32路同素材，5/8GT下各none/sync10；先保留无追踪窗口，再分组追踪。先0.2秒冒烟验证实际内联后的调用层级，再取最小必要深度做2–4秒窗口。现有浅层depth=2看不到VPP描述符上传内部的mutex等待，旧trace不能直接补算这部分。

追踪前后核对INF、TPU、实际预览率、最慢路和停顿；保留每CPU丢事件/overrun与不完整调用比例，采集结束恢复原tracer/filter/buffer设置。深度和逐MMIO追踪可能显著扰动业务，追踪值只能作为该追踪条件下的观测，不替代无追踪性能。

解析按TID维护调用栈，统计完整落窗的根调用，丢弃边界不完整调用。父子耗时包含关系不能重复相加：VPP总时间包含描述符上传，上传又包含CDMA锁等待。TPU提交中多把锁可能在同一父函数调用 `mutex_lock`，普通函数图缺锁地址，第一轮只能报“提交路径锁等待合计”；不能直接给其中某把锁单独归因。

## 两个驱动计数盲点

1. VPP描述符上传经 `bmdev_memcpy_s2d_internal` 调用CDMA时，传入 `file=NULL`，没有关联用户线程 `ti`；而 `bm1684_cdma_transfer` 的profile计数和时间增加都受 `if(ti)` 条件控制。因此 `/proc` 的CDMA累计计数不覆盖该类描述符上传，不能代表整个系统的全部DMA及指令开销。
2. `cdma_mutex` 取得后还检查 `TOP_CDMA_LOCK`，驱动注释说明这是等待ARM9侧释放CDMA资源。锁内时间还包含硬件锁检查、寄存器配置、轮询/中断等待，不能全部当作纯PCIe数据搬运时间。

若要计算**命令有效字节率**，还需采集VPP实际 `batch->num × sizeof(descriptor)`、TPU实际消息参数长度等。函数图只给函数和时长，没有这些参数；必要时才增加针对参数/调用位置的探针或受控计数。PCIe线上协议开销、TLP数量、真实物理利用率则需要可用的链路计数器或硬件分析手段，不能从SDK墙钟反推。

本页完成的是第一层“调用开销”复算；后续采集已确认具体等待案例，但稳定的业务用途分账、命令字节计数和物理总线测量仍未完成，不能据此宣布根因比例已经确定。
