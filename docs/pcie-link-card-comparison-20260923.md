# PCIe2 x1 与 PCIe3 x1 跨卡对照（已完成）

> 阅读顺序：补充。主要目的：记录跨卡差异；接口因果关系优先参考同卡变速报告。 [返回阅读导航](pcie-reading-guide.md)。

设备0为0002:21:00.0，5GT/s x1；设备2为0003:31:00.0，8GT/s x1。不是历史PCIe3 x2。采用同一build-async二进制、32路原1080p24长素材、gate64reuse、结果回传开启，分别测无预览、同步10FPS预览上限、异步3FPS预览上限。

设备顺序0→2→2→0，后两批反向配置顺序；另一卡空闲。每档30秒预热60秒正式，共12阶段，预计20–25分钟。输出data/results/link-card32-20260923，入口run_link_card_ab.py，监督脚本.tools/link_card_supervisor.py。检查链路、设备BDF及文件哈希。

本轮为跨卡对照，不等同同卡强制降速；不能将卡、插槽、拓扑差异全部归为PCIe代际。各卡每种配置按相同口径比较吞吐、TPU、预览、最差单路、空窗及SDK墙钟等待。12阶段均正常完成。

同一sync10程序和素材，PCIe3 x1卡推理高约21.8%，TPU95.43%而PCIe2为78.03%；缩略图VPP SDK调用约16.84ms对32.78ms。差异已复现，但这些是调用墙钟、不是纯硬件执行时间，也未在PCIe3卡采集驱动准入等待，因此不能据此断定全部由PCIe线速造成。

PCIe2 async3为266.93FPS/97.49%，最长空窗0.226秒；PCIe3 async3为273.48FPS/99.83%，但最长空窗1.552秒。不要用高TPU掩盖连续性问题。sync10到async3同时改变调度和预览频率，不是单变量收益；同频异步证据见既有预算实验。

四批输入、模型、二进制哈希一致；同配置命令除device、output、readback-control路径外完全一致。565个原始普通文件逐一SHA256校验一致，12个FIFO不复制。原始目录data/results/link-card32-20260923，分析analysis.json，校验verification.json。

结论：同样的程序在不同卡/链路上等待与吞吐不同，不能归结为与平台无关的纯程序问题。已有PCIe2 VPP准入排队证据；下一步应在PCIe3 x1采集相同口径驱动调用图，区分准入、命令传送和完成等待，再决定是否值得做同卡链路降速。当前只是跨卡关联证据，未证明PCIe代际因果，也不代表长期稳定性验收。


## 同口径跨卡VPP驱动追踪：未解释两卡性能差异

独立使用同一build-async、sync10、32路原素材，device0后device2，各20秒预热20秒测量，约4秒function_graph窗口，max_depth=2、sleep-time开启、每CPU8192KiB。非前述无追踪正式对照，不能混算吞吐。

| 平均耗时 | PCIe2 x1（4517次完整调用） | PCIe3 x1（5070次完整调用） |
|---|---:|---:|
| bm1686_trigger_vpp整体 | 40.688ms | 41.079ms |
| down_interruptible准入 | 39.000ms | 39.583ms |
| bmdev_memcpy_s2d_internal命令传送 | 0.596ms | 0.423ms |
| schedule_timeout完成等待 | 0.995ms | 0.976ms |

结果不支持“PCIe3的VPP准入排队必然更短”的解释：本次追踪两卡均大量等待且均值接近。命令传送调用PCIe3约少0.174ms，但不能将其直接解释为无追踪预览SDK调用约16ms差距。请求数、请求来源、队列深度不同，且函数图会改变调度；两个均值相近不代表原始性能相同。

因此已证实的范围应保持为：VPP准入竞争和应用同步依赖存在；无追踪跨卡性能差异可复现；本轮驱动追踪未解释跨卡差异。不能把资源等待直接定性为PCIe2专属问题或VPP硬件计算饱和。下一步应使用低扰动固定图像VPP探针，统一操作规格和并发数（1/2/4/8/16/32），分别比较无排队服务时间与并发扩展，再按需要考虑同卡链路降速验证。

两个追踪窗口所有CPU均无overrun/commit overrun/dropped events。91个普通文件SHA256一致，证据目录data/results/vpp-link-graph-20260923。trace设置恢复原nop、7KiB和原选项，无驱动修改。
