# 如何理解 Demo 的性能数据

[仓库首页](../README.md) · [运行配置](../demos/hdmi_wall/docs/linear-materials.md) · [技术报告导航](pcie-reading-guide.md)

这个 Demo 展示在 RK3588 主机上使用 BM1684X 卡进行多路视频解码、目标检测和 HDMI 预览。下列结果来自指定设备与素材的测试，帮助理解已经做到什么，以及如何复现。

最新记录见[三卡 96 路五分钟测试](../demos/hdmi_wall/docs/three-card.md)：两张 PCIe2 ×1 与一张 PCIe3 ×1 卡同时运行，合计约 840.10 FPS，卡 0 有年龄超限丢帧。下表保留 09-28 双卡短测，帮助理解指标，不能代替三卡结果。

## 路数与画面流畅度

本轮三卡并发、每档正式 45 秒，不限频预览、播放器 30 FPS：每卡 4 / 8 路时平均每路预览提交约 24 FPS，16 路约 17–18 FPS，24 路约 11–12 FPS，32 路约 7.5–8.7 FPS。截图、各卡数据与命令统一见[视频墙五档说明](../demos/hdmi_wall/docs/layouts.md)。

32 路可以同时检测和展示，但当前 YOLOv8s 与检测后更新预览的流程达不到每路 24 FPS。这个结论限定本轮设备、模型、素材与配置，不代表 BM1684X 的所有模型或纯解码场景上限。

## 双卡短测的指标示例

2026-09-28，两张卡同时运行，每卡 32 路，分别使用 PCIe 2.0 ×1 和 PCIe 3.0 ×1。模型为 YOLOv8s INT8，每路独立读取同一份官方 1080p、24 FPS 本地视频；采用线性解码输出、8 块额外缓冲，保留检测结果回传，每路预览上限 3 FPS。每卡正式测量 60 秒，不包含初始化和预热。

| 指标 | PCIe 2.0 ×1 | PCIe 3.0 ×1 |
|---|---:|---:|
| 32 路合计检测速度 | 280.30 帧/秒 | 281.43 帧/秒 |
| 按 32 路计算的平均每路检测速度 | 8.76 帧/秒 | 8.79 帧/秒 |
| 最慢一路检测速度 | 8.73 帧/秒 | 8.75 帧/秒 |
| TPU 利用率采样 | 12 次均为 100% | 12 次均为 100% |
| 所有通道在测量期间都有检测结果 | 是 | 是 |

检测次数分别为 16,818 和 16,886，除以 60 秒得到总检测速度。每路平均值再除以 32；最慢一路单独统计，不能用平均值代替。[可随仓库获取的数据摘要与源文件校验值](../demos/hdmi_wall/docs/data/linear-showcase-20260928.json) · [原始运行编号、配置和连续性记录](../demos/hdmi_wall/docs/linear-materials.md)。

源视频每路每秒有 24 帧，检测平均每路每秒约 8.8 帧。程序优先分析较新的画面，会覆盖尚未处理的等待帧。因此，“过期丢帧为 0”只表示没有因超过年龄门槛而丢弃，不能简写为“零丢帧”或“所有帧都检测”。

## 这次优化解决了什么

原路径在解码后还会展开一种压缩的图像内存布局。这个步骤与检测前的缩放、预览处理争用图像处理资源，排队使检测计算单元等不到新图像。在本次 PCIe2 业务中，这构成了主要性能卡点。

改为直接输出线性图像后，可以去掉这一步额外展开；增加解码缓冲，让下游仍持有图像时，解码器有空间继续工作。这里的“线性”是内存布局，“8 块额外缓冲”是解码图像缓冲，都不表示改了视频帧率或增加了推理队列。

这一机制通过格式和缓冲对照验证，详见[根因报告](vpp-root-cause.md)。上表最终展示配置还包含输出复用、结果合并读取和降低预览频率；不能把最终数字相对任意旧版本的全部收益，都归到线性输出一个改动上。

## 常见数字该怎么读

| 常见说法 | 准确含义 |
|---|---|
| 32 路 | 同时处理 32 个视频通道；本次各通道读同一本地文件，未验证 32 个独立网络摄像头。 |
| 280 FPS | 一张卡上 32 路合计的检测速度。 |
| 32 × 24 = 768 FPS | 源视频合计帧率；逐帧检测才需要达到相同检测速度。 |
| TPU 100% | 查询时得到的利用率样本；不等于每一瞬间都满载，也不等于达到芯片理论峰值算力。 |
| 预览 3 FPS | 每路预览的配置上限；实际新画面率需单独统计，和 HDMI 显示器刷新率不同。 |
| 约 372 次/秒 | 历史驻留模型探针的速度，不含完整视频处理流程，不能作为视频检测交付指标。 |
| PCIe2 只能跑 20 路 | 这是旧配置的历史档位，不能作为当前容量上限。 |

## 历史数据与当前结论

历史数字保留其原测试条件：早期 PCIe3 ×2、后来的 PCIe3 ×1，以及同卡变速对照，不能直接合成一张“接口性能排名”。同卡对照用于研究接口影响；当前两卡并行短测用于验证展示配置。

上述双卡记录为 60 秒；后续三卡记录为每卡 300 秒。另有历史 PCIe3 ×1、24 路配置的一小时记录，它不是当前 32 路方案的长稳证明。默认可运行四小时是程序设置，四小时稳定性仍需单独测试。

更换素材也需要重新确认路数：同轮 highway 1080p25 素材在 24 路时各通道都有结果，32 路对照出现部分通道无结果。不能把官方 1080p24 的 32 路成绩推广到所有视频、摄像头或场景。
