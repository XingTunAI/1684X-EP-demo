# PCIe2 32 路全流程耗时与开销

> 阅读顺序：补充。主要目的：解释早期30分钟本地循环视频的阶段计时，不能作为纯硬件时延或稳定性验收。 [返回阅读导航](pcie-reading-guide.md)。

采用恢复官方 1080p24 素材后的 30 分钟观察，device 0 / PCIe2×1，结果回传开启、每路预览上限 10 FPS。总推理 201.44 FPS，实际平均每路预览 4.56 FPS，TPU 平均 73.56%。不涉及视频编码。

所有时间按各路累计 sum / 累计 count 加权，不能平均各路分位数。它们是 SDK 调用或程序阶段的墙钟时间，包含并发排队、同步等等待，不等于硬件独占执行时间。

| 环节 | 平均耗时 | 统计口径和开销 |
|---|---:|---|
| 主控读文件、解封装、上传压缩视频 | 未单独测量 | 不能从现有统计拆出磁盘、CPU 和 H2D 各自耗时/流量；部分包含在取解码帧调用中 |
| 获取解码帧 | 39.66ms | 仅统计最终完成分析的帧；不是全体解码帧平均，更不是独立 VPU 执行时间 |
| 解码后等待送检 | 21.70ms | 解码完成至被推理线程选中；latest 只保留最新等待帧 |
| 图像桥接 | 0.009ms | 该路径主要复用设备图像，不等同于回传完整 BGR 图像 |
| 推理预处理 | 70.13ms | 图像准备和模型输入预处理相关调用，含竞争和等待 |
| 主模型推理 | 17.94ms | 提交约 0.089ms、同步约 17.839ms；不能当作模型核心独占时间 |
| 结果筛选计算与同步 | 16.74ms | score-gate 辅助模型阶段，是计算/等待，不是 PCIe 复制 |
| 读取分数 | 1.89ms | 33,600 字节/次，SDK 调用含等待 |
| 读取候选区域 | 11.64ms | 筛选和合并后的候选读取，数据量随画面变化，SDK 调用含等待 |
| CPU 检测后处理 | 0.093ms | 当前优化路径的后处理，不是整机 CPU 总开销 |
| 缩略图生成 | 35.11ms/张 | 卡上 VPP 缩放/色彩处理调用，含等待 |
| 缩略图回传 | 2.50ms/张 | 256×144×3=110,592 字节 |
| 主控画检测框 | 0.044ms/张 | 不包含完整墙面合成和播放器 |
| 提交缩略图到显示模块 | 0.128ms/张 | 不是物理 HDMI 出画面延迟 |
| 视频墙合成、FIFO、播放器、HDMI | 未单独拆分 | 显示线程异步运行；不能拿提交耗时代替屏幕延迟 |

结果获取整个阶段约 30.43ms，其中 16.74ms 为筛选阶段，1.89+11.64=13.53ms 为结果读取调用，另有少量规划等开销。不要在 30.43ms 之外再次叠加这些子项。

缩略图整个阶段约 37.79ms/张。正式窗口完成分析 362,597 帧，其中 262,528 帧提交预览，约 72.4%；摊到全部分析帧的预览耗时约 27.36ms，不是每帧都增加 37.79ms。

## 一帧时间线与吞吐的区别

- 从选中帧到检测结果完成（service）：118.65ms，包含预处理、模型、筛选、读取和后处理。
- 从开始获取解码帧到预览处理完成并记账：207.39ms。可用 39.66+21.70+118.65+约27.36ms 核对，少量差额来自其他处理。
- 从原视频计划播放时刻到检测完成：211.99ms，仅统计已完成检测帧，不含屏幕等待，也不覆盖未产出结果的空窗。
- 32 路并发、解码和分析跨帧重叠，不能用 1000/207.39 得出整卡 FPS，也不能把所有阶段时间加成硬件串行耗时。

## 流量

结果平均 119.37KB/次检测，实际累计 24.05MB/s。缩略图 110.592KB/张，实际累计 16.13MB/s。两项有效载荷合计 40.18MB/s，不含码流上传、控制/协议、其他未计数传输，不是总线利用率。模型初始化不计入正式窗口，不会每帧重新加载权重。

## 判断

可观测的长耗时在预处理、缩略图 VPP 和结果筛选/读取等待；CPU 画框和检测后处理在已测范围内很小。不能凭单项调用耗时就认定对应硬件已饱和，也不能将 40.18MB/s 解读为 PCIe 带宽打满。

短测无预览时仍有结果回传，TPU 96.22%、264.45 FPS；开启 10 FPS 预览上限的短测为 76.61%、211.87 FPS，说明预览整条处理链存在明显成本，不证明其中全部成本都是像素传输。

30 分钟内最大分析空窗达到 99.09 秒，长空窗与 600 秒本地文件循环重开时刻对应。已完成帧的平均耗时不能掩盖该问题；当前不能作为稳定告警验收。
