这是单次顺序短测，没有随机化或交换顺序复测，也不是摄像头告警/长稳验收。历史约 95.18% 来自另一环境的双卡运行和多设备播放器；本轮单卡使用 ffplay，恢复的是核心业务参数，不是完整历史环境。不能将两轮差值全部归因于某一项。

## 30 分钟观察结果：本地文件循环会触发长时间分析空窗

观察运行已正常结束，32 路账目完整。预览上限 10 FPS、结果回传开启，正式 1800 秒：

| 指标 | 实测 |
|---|---:|
| 总解码 FPS | 767.37 |
| 总推理 FPS | 201.44 |
| 最低单路平均推理 FPS | 5.79 |
| TPU 平均 / 有效采样 | 73.56% / 1798 |
| 实际平均预览 FPS/路 | 4.56 |
| 最长无推理结果区间 | 99.09 秒 |
| 模型结果 / 缩略图有效载荷 | 24.05 / 16.13 MB/s |

该结果不能作为稳定实时告警验收。全场每路都有结果不代表每路连续有结果；平均解码接近目标也掩盖了局部时间落后。

长空窗集中从正式窗口约 570.95 秒、1171.45 秒开始。素材长约 600 秒，预热 30 秒，因此这些时刻对应本地文件第一次、第二次循环重开附近。CH04 在第一次循环附近的逐秒快照中约 98.60 秒推理计数不增长，但解码增加 2384 帧；正式连续性统计给出 99.09 秒的最大推理间隔。CH21 同次循环也出现约 95.55 秒推理间隔。支持“循环重开后落后，继续解码旧内容而无法稳定通过送检年龄门槛”的机制；尚未单独隔离重开成本与硬件资源竞争，不能把全部原因归为 PCIe 带宽。

下一步应先使用覆盖整场时长的长文件消除测试中的循环重开因素，再检查预览开销和短时停顿。不得通过重置源时钟或直接关闭过期门槛，把旧帧伪装成实时恢复。真实摄像头没有这个本地 EOF 循环，但网络中断或积压恢复仍需独立验收。
